# Reproduce the three paper extensions

Run from the repository root with Python 3.11+. No Suricata traffic replay is needed: this evaluates existing offline alerts.

```powershell
python -m pip install -r requirements.txt -r requirements-benchmark.txt -r requirements-experiments.txt
$env:PYTHONPATH='src'
python -m as_engine.human_study prepare
python scripts/download_ait_validation.py --output work/ait_validation_data
python -m as_engine.external_validation --data-dir work/ait_validation_data/data --labels-dir work/ait_validation_data/labels --scenarios russellmitchell shaw wardbeck santos --repeats 5
python scripts/benchmark_controlled.py
python scripts/report_paper_extension.py
python -m unittest discover -s tests -v
```

On Bash use `export PYTHONPATH=src` in place of the PowerShell environment assignment.

Send each rater only their `runs/paper_extension/human30/rater_N` folder. Keep `coordinator` private. After the same three experienced raters complete all 30 items and the responses are frozen:

```powershell
python -m as_engine.human_study analyze --key runs/paper_extension/human30/coordinator/annotation_key.csv --responses runs/paper_extension/human30/rater_1/responses.csv runs/paper_extension/human30/rater_2/responses.csv runs/paper_extension/human30/rater_3/responses.csv --output runs/paper_extension/human30/analysis.json
```

Blank responses intentionally fail validation. The analysis command does not verify professional experience; the coordinator must document eligibility. Nonfinite/undefined statistics are serialized as JSON null. The number of finite bootstrap estimates is reported; intervals with many undefined replicates require particular caution.

The external runner uses the exact same scoring YAML, metadata catalog, profile and adapter for all scenarios. It records input hashes, configuration hashes, software/environment information, per-run logs, raw measurements, coverage and leave-one-scenario-out macro means. The three additional scenarios were chosen before scoring as the smallest remaining Wazuh exports, not because their scores supported a preferred conclusion. They are a limited convenience sample, not a random sample of all AIT-ADS scenarios.

Download is outside the benchmark. Every stage runs in a fresh process, once for warmup and five times for measurement; disk caches are not flushed. Process wall time includes interpreter startup and output I/O. CPU time covers the target module after the measurement wrapper initializes. Peak RSS is the OS high-water resident/working-set value, including the Python runtime, rather than Python allocation tracking. Report median and min–max across repeated runs. Do not add stage memory values; sequential pipeline peak is approximated by the maximum stage peak. Summed stage medians describe component cost, not a directly measured end-to-end latency.

The benchmark covers offline adaptation, correlation/scoring and aggregation. It excludes live Suricata detection, packet ingestion, long-running retention, analyst labor and monetary infrastructure costs. The 500 controlled presentations are transformations of 10 seeds and their experiment-generation cost must be reported separately from raw-alert throughput.

AIT labels are time-phase labels joined by timestamp/signature, not verified maliciousness for every individual alert. Archetypes reduce duplicate frequency but are not guaranteed independent incidents. Report cross-scenario results descriptively; similar score means do not establish statistical equivalence or human validity.

The deliverable includes compact summaries, archetype tables, logs and measurements. Large derived EVE/score files are regenerated by the commands above and are excluded from the delivery archive.

## Optional performance recheck and paper figure

The delivered experiment retains a second measurement batch because the first showed substantial timing variation. Reproduce it before generating the comparison figure:

```powershell
python -m as_engine.external_validation --data-dir work/ait_validation_data/data --labels-dir work/ait_validation_data/labels --scenarios russellmitchell shaw wardbeck santos --repeats 5 --output runs/paper_extension/external_recheck
python scripts/verify_paper_extension.py
python scripts/report_paper_extension.py
python scripts/plot_paper_extension.py
```

Do not run benchmarks concurrently with other compute-intensive tasks. Even with sequential stages, a personal machine's background load, power policy and temperature are not controlled here. Preserve both batches; do not select whichever timing supports a preferred claim. Figure whiskers show observed min-max, not confidence intervals.

## Statistical implementation note

Ordinal alpha uses category-frequency distances, following [Krippendorff, Computing Krippendorff’s Alpha-Reliability, p. 6](https://www.asc.upenn.edu/sites/default/files/2021-03/Computing%20Krippendorff%27s%20Alpha-Reliability.pdf). The previous implementation used squared numeric differences, an interval metric. The pilot analyzer also preserves undefined correlations as null rather than treating constant vectors as zero correlation. The reported AUPRC uses stepwise average precision, not trapezoidal integration. See regression tests for nonuniform category frequencies and constant scores.
